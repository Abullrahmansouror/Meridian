# Repository Guidelines

## Project Structure & Module Organization

This is a Next.js 16 App Router site written in TypeScript. Routes and SEO endpoints live in `app/`; project detail pages are generated by `app/projects/[slug]/page.tsx`. Reusable primitives belong in `components/ui/`, navigation and footer elements in `components/layout/`, and homepage sections in `components/home/`.

Keep copy and structured content in `lib/data/`; components should not duplicate it. Shared helpers are in `lib/utils.ts`, motion settings in `lib/motion.ts`, and design tokens in `app/globals.css`.

## Build, Test, and Development Commands

- `npm install` installs dependencies from `package-lock.json`.
- `npm run dev` starts the local Turbopack development server at `http://localhost:3000`.
- `npm run build` builds, type-checks, and prerenders routes.
- `npm run lint` runs the Next.js Core Web Vitals and TypeScript ESLint rules.
- `npm run check` runs both required verification commands.
- `npm run start` serves a completed production build locally.

## Coding Style & Naming Conventions

Use strict TypeScript, two-space indentation, double quotes, semicolons, and the `@/` import alias. Name React components and their files in PascalCase (`ProjectCard.tsx`); use camelCase for helpers and data exports. Prefer Server Components, adding `"use client"` only for browser state, interaction, or animation.

Compose new UI from existing primitives first. Use Tailwind utilities and tokens from `app/globals.css`; preserve the blueprint aesthetic, mono labels, and single amber accent. Store Unsplash photo IDs in data and render them through `img()` and `next/image`.

## Testing Guidelines

There is no test framework or coverage target. Run `npm run check` and inspect affected routes at mobile and desktop widths. Exercise controls, keyboard focus, reduced-motion behavior, and responsive navigation. Colocate future tests as `*.test.ts` or `*.test.tsx`.

## Commit & Pull Request Guidelines

The short history uses concise, imperative summaries; continue with focused subjects such as `Add careers filtering`. Keep commits scoped to one concern. Pull requests should explain the user-visible change, list verification performed, link relevant issues, and include before/after screenshots for visual work. Call out placeholder content, mocked integrations, or follow-up configuration explicitly.

## Architecture & Configuration Notes

Every page should begin with a dark hero so the transparent header remains legible. Keep `MobileNav` as a sibling of `<header>`, not its child. Update the production URL consistently in `app/layout.tsx`, `app/sitemap.ts`, and `app/robots.ts`. Never commit credentials; use local environment files for future service integrations.
